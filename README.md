# 抖音千川素材编导 Agent

专门给抖音千川素材编导使用的开源 Chrome / Edge 本地扩展。它保留用于快速复盘与下一版决策的侧边栏编导工作区，同时提供独立的全页“素材处理与分析工作台”。

它把可选创作任务、历史素材复盘、单变量测试策略和拍摄生产资料放进同一个本地工作区。编导无需先填写商业资料；导入千川素材报表后，即可得到下一版素材的测试假设、口播稿、分镜、拍摄任务单、剪辑要求、字幕重点与合规检查。

> 核心目标不是“多生成几条通用文案”，而是帮助编导基于历史证据决定下一批拍什么、只改什么、如何验证。

功能保留、降级、合并和删除的判断标准见 [`docs/PRODUCT_AUDIT.md`](docs/PRODUCT_AUDIT.md)。

## V1.4.0 能做什么

V1.4.0 增加由编导手动维护的制作进度：未标记、待拍、拍摄中、剪辑中、待投放、已上线和已搁置。每个测试版本都可单独更新状态，顶部行动台和“实验下一步”会优先定位真实制作动作；只有明确标记为“已上线”且尚无结果的版本才会被主动提醒回填。生成、复制或导出方案不会自动变成待拍，导入结果也不会反向篡改制作状态。

制作进度、更新时间与版本一起保存在当前扩展来源的 IndexedDB，并进入用户主动导出的项目备份和实验台账。旧 V1.3 项目没有该字段时统一显示“未标记”，不会被猜测或强制迁移；状态可由编导随时修改或清除。

每个实验版本的“制作与投放交接”层新增一张本地投放交接卡。复制前会检查制作阶段、基线、唯一变量、本条变量值、测试假设、保持不变项、观察指标、最低消耗、项目目标 ROI、停止条件、达成后动作和单变量一致性。变体优先与同批次唯一 B00 基线对照，跨轮基线按明确父版本对照；批次或基线不可唯一确认时只提示人工核对。缺项卡仍允许在二次确认后复制并保留“待补充”，不会自动补写、创建广告计划、设置预算、启停投放、读取账户或改变版本状态。

实验区顶部同时提供“最新批次投放交接”。它按方案生成时间选择最新批次，固定把 B00 放在变体之前，展示每条版本是否可交接、整批版本就绪数和检查项通过数；操盘手可以一次复制包含执行顺序和全部单条卡片的交接包。缺项批次必须再次确认，超过 40 个版本的异常大批次会要求拆分，避免侧边栏和剪贴板生成过大文本。批次选择、排序和完整度只在当前页面计算。

为了让团队成员获得灵感而不是照抄素材，实验区新增默认折叠的“灵感接力”。它只从最新批次抽象开场叙事、价值表达、场景表达或受众切片机制，把相近方向去重为最多 6 张灵感卡，并给出启发问题、证据状态和三项原创改写动作。除复制整包外，每张卡都能一键复制“共创挑战”：分别从同机制新场景、反向机制和新证据路线发散，并要求交付单变量假设、前三秒、受众场景、可核验证据、节奏/行动引导和停止条件。导出的接力包与挑战题都不会包含项目名、测试或批次编号、素材名、指标数值、完整脚本、具体品牌主张或本机信息；“达到本地目标”等标签只说明来源版本的描述性状态，不证明某个机制导致效果。

V1.4.0 同时把独立工作台的高频路径收短：“分析已有转写”置于首选推荐位，选中后会暂时收起本轮不需要的视频选择与 FFmpeg 处理区，并把前两步明确显示为“本轮跳过”；切回视频入口即可恢复原区块，已有文件、任务、正文和分析不会被清空。转写文件、执行结果和会话交接还增加了“只接受当前最新操作”的页面级保护，快速换文件、重建任务或重置本轮后，较早完成的异步读取不会反向覆盖较新的状态。

V1.3.0 把单次方案生成升级为本地创意实验闭环。侧边栏顶部可新建、重命名和切换最多 20 个编导项目；旧版最近一个工作区会自动成为第一个项目，不需要手工迁移。每个项目独立保存创作任务、复盘摘要、方案与导出状态，项目集合、测试版本、结果和人工决策记录使用当前扩展来源内的 IndexedDB 保存。

顶部“今日编导行动台”把当前项目的策划交付、实验待办和最新批次单变量风险合并成最多 3 项可执行动作。它优先处理复盘失效、人工决策失效、指标口径提醒与内容变量风险，再提示待决策、待回填或常规生成/导出；点击后会直接定位到对应表单或父子内容 Diff。行动台只描述能从本地状态确认的事实，不把“有方案”虚构成“拍摄中”或“已上线”，也不会自动提交、回填、保存决策或生成新方案。

生成方案时会创建带毫秒批次时间的唯一测试编号。编导可以显式选择父版本，也可以把本轮作为新的测试起点；系统不会自动猜测血缘。上线后既可导入最大 2 MB、1,000 行的 CSV / TSV，也可直接手动回填单个版本的消耗、ROI、成交金额、漏斗和播放指标。手动回填会预载已有指标，先经过与批量导入相同的数值、漏斗和口径校验，再由用户二次确认是否替换旧结果。

实验区的“实验下一步”行动卡按“失效决策 → 口径提醒 → 可记录决策 → 缺少指标 → 已上线待回填 → 制作进度 → 样本不足”的顺序提示当前最需要处理的一条记录，并通过测试编号精确定位到对应制作状态、决策或快速回填表单。当待办处理完成后，它只从证据仍有效的人工结论中建议下一轮父版本：“保留方案”优先，其次是“继续测试”；“停止测试”和待重审结论不会被推荐。建议必须由用户点击才会选中，仍不会自动生成方案。版本可组合使用结果、人工决策、制作状态、批次和编号/父版本/变量搜索，每页只渲染 20 张卡片，单项目上限内的 500 个版本均可分页到达。完整台账可导出为 CSV 或 JSON。

每个测试版本现在都有折叠的“人工决策”卡。编导需要选择继续测试、保留方案或停止测试，指定主指标与可选护栏指标，并填写判断理由。系统把当时的结果导入时间、描述性状态、目标 ROI、最低消耗和版本内容做成本地证据指纹；结果被重新回填、目标 ROI 或最低消耗改变、版本内容变化后，旧决策自动标记为“需重新确认”，但仍保留供审计。

首次打开仍会显示可收起、可重新打开的三步引导：“导入历史报表 → 完成素材复盘 → 生成并导出任务”。侧边栏顶部保留“策划交付”进度与一条下一步，并由“今日编导行动台”补充最多两条实验或内容核对动作。导出只表示策划交付完成，界面会继续引导进入批次拍摄和逐条现场快检，不会把它称为整轮制作完成。创作任务始终是可选上下文；系统会用规范化后的字段映射、复盘排名、标签、ROI、创作任务、测试变量和最低消耗生成依赖指纹，其中任一项变化都会让旧方案明确失效。V0.6.1 及更早方案没有该指纹，恢复后会安全降级为“需要重新生成”，不会崩溃或继续导出。

V1.3.0 延续独立工作台从“结构分析”到“下一版可拍任务”的能力。TXT、MD、SRT、VTT 和手动粘贴正文会统一进入 Transcript v2：记录来源类型、格式、语言、分段、时长、解析器版本、本地内容指纹和解析提醒。SRT / VTT 保留每个 cue 的开始时间、结束时间、标签和正文；TXT / MD 使用无时间的段落来源。旧 V1 转写对象只在内存中升级，原对象不会被覆盖；用户手动编辑正文后，旧时间或段落映射会立即明确失效。

草稿包含本地唯一测试编号、父版本、匿名来源分析编号、问题摘要、测试假设、保持不变项、前三秒钩子、口播稿、分镜、补拍镜头、字幕重点、剪辑节奏、成功指标和停止条件。生成器是本地确定性模板，不预测投放效果；事实、证据、合规表达和指标阈值必须由编导人工核对。任何编辑都会撤销旧确认，只有重新明确确认后才能发送 V2 会话交接或导出 V2 交接包。

V1.3.0 同时保留完整会话生命周期。首屏始终显示低强调的“开始新一轮 / 重置本轮”；当本页已有视频、路径与授权参数、处理或转写任务、正文、分析、草稿、交接状态或错误时，必须先确认才会重置。确认文案会特别指出尚未导出的任务、分析和草稿；取消时不改变任何内容。确认后只复位当前工作台页面内存和界面，绝不会删除原片、已下载文件、侧边栏内容、`chrome.storage.local` 工作区、IndexedDB 项目集合或已经发送到会话收件箱的结果。

V1.0.6 在独立工作台首屏提供“处理本地视频”和“分析已有转写”两个入口，不再默认把所有用户引向视频选择。选择已有转写后，顶部唯一主操作会直接打开本地 TXT、MD、SRT 或 VTT，也可以从首屏聚焦正文粘贴区；不要求先授权视频或生成 FFmpeg 任务。入口只存在于当前页面内存，切换时会保留并提示已有视频选择、任务、正文和分析结果，不新增持久化记录。

V1.0.5 将独立工作台收口为一条由顶部唯一主操作驱动的流程。按钮不再只负责滚动定位，而会根据真实状态依次选择素材、补齐校验、生成任务、导出清单、导入本机结果、导入转写、分析结构并发送编导台。首屏同时显示统一阶段、四步状态、完成度、下一步原因和集中错误；分区按钮仍作为辅助入口保留。所有动作仍由用户逐次点击，不会自动启动本机程序或绕过授权与文件校验。

V1.0.5 延续 V1.0.4 的可审查交接链路：工作台可把固定 schema 的结果一键放入 `chrome.storage.session` 单槽收件箱并尝试打开侧边栏，也继续提供本地 JSON 备用。会话结果两小时后失效；同一分析重复发送保持幂等，不同待处理结果不会被静默覆盖。侧边栏先校验和预览，再由用户勾选并确认填入空白的“目标受众、受众问题、核心主张、可用证据”。它不会自动覆盖已有任务内容，不包含原始转写全文、文件名、视频信息或本机路径，也不会把确定性规则描述成投放效果预测。

V1.0.5 延续 V1.0.2 的首屏工作台入口、最近任务继续卡和逐键工作区恢复：单条损坏记录不会阻止页面启动；界面会列出具体异常键，只有用户显式点击并再次确认后才清理。读取或保存失败时，当前会话仍可继续导出，且不会自动删除其他正常数据。

### 1. 创作任务（可选）

- 记录素材主题、目标受众、创作目标、受众问题、核心主张与可用证据
- 记录拍摄条件、风险备注和目标视频时长
- 提供效果验证、场景共鸣与人物故事三种通用起步模板
- 所有字段均为可选；不填写主题也能复盘和生成下一版任务
- 自动保存在当前浏览器的本地存储中

### 2. 素材复盘

- 导入 UTF-8 CSV / TSV 报表
- 报表最大 8 MB、50,000 行和 200 列；未闭合引号、空白或重复表头会在分析前拒绝
- 预览前 5 行，避免导错文件
- 自动识别常见千川字段别名，并允许手动调整字段映射
- 明确提示缺失的必需字段和可选指标
- 在分析前补齐或修改人群、前三秒钩子、核心主张、拍摄场景标签
- 结合样本量、消耗、CTR、CVR 和目标 ROI 输出诊断与置信度
- 导出复盘 JSON 或 Markdown

### 3. 下一版任务

- 从表现较好的历史素材中选择基线
- 每轮只测试一个变量：钩子、核心主张、场景或受众
- 每个方案包含测试假设、基线、唯一变量、保持不变项、观察指标、最低测试消耗、停止条件和成功后动作
- 根据可选创作任务与历史基线生成可编辑的口播稿、镜头级分镜、拍摄任务单、剪辑要求、字幕重点和合规清单
- 默认提供“复制开拍清单”：按基线 → 变体顺序提炼每条唯一变量、前三秒、现场必拍、剪辑交付、字幕和发布前检查；完整策略仍可单独复制或导出
- 开拍准备检查会逐条标出缺失的现场字段并随编辑即时更新；“定位下一个缺项”会按方案与字段顺序展开对应卡片并聚焦准确输入框，补齐后继续指向下一项。不完整清单仍可由编导确认后复制，但系统不会自动补写或把“字段齐全”解释为创意有效
- 每张方案卡在长表单之前提供“片场执行条”，先显示拍摄顺序、B00 / 变体身份、唯一变量与本条变量值，以及本轮必须锁定的固定项；编辑后顶部摘要同步更新。只有本条开拍字段齐全、方案未过期，且整批保持 B00 → 连续 A 编号、类型与批次归属一致时，才可复制“本条开拍单”；它只复制当前方案，不写完成态或制作状态。同一区域继续保留“前三秒现场监看卡”，开机时无需翻到表单底部。
- 每条方案都可复制独立的“前三秒现场监看卡”：按 0–1 秒首帧、1–3 秒钩子/口播/字幕和 3 秒后证据承接组织现场指令，同时提供手机停帧、真人盲读、单变量核对与返拍触发条件。缺少证据镜头等关键字段或方案上下文已经过期时按钮关闭；信息密度和钩子—口播错位只作为人工复核提醒，不构成质量评分。卡片状态、复制和事件生命周期由独立控制器管理
- 同一执行条新增“拍后快检卡”：每个 Take 拍完立即登记实际文件、Take 与声音条，再人工检查静音首帧、有声钩子、证据连续、固定项连续、声音与剪辑余量，并在“保留本 Take / 立即重拍 / 停机核实事实或授权”中三选一。提醒只决定重点回看内容，扩展不会读取媒体、自动评分、自动选 Take 或写入制作状态
- 默认折叠的“前三秒拍前盲审”会在本地稳定打乱 2–12 条同批方案，并按 `1 盲审 → 2 揭晓 → 3 合议` 固定顺序呈现：评审者先复制只含受众、场景、首帧、钩子、字幕和证据预期的公共盲审包，导演锁定反馈后再单独复制真实映射，最后生成同编号合议单。公共包看不到测试编号、基线身份、来源素材、金额或历史指标；任一内容修改都会生成新的盲审编号
- 导演合议单要求逐条填写一秒理解、继续观看、共同证据预期、重复歧义与原创新开场，再人工选择保留开拍、单变量重写或本轮淘汰。系统不按票数自动判胜，也不会把盲审偏好写成投放效果结论；三个按钮的等待、过期、阻断与就绪状态以及剪贴板分支由独立控制器统一管理
- 默认折叠的“批次拍摄与成片交付”按 `1 拍摄 → 2 接片 → 3 剪辑 → 4 验收` 排列四个动作：拍摄镜头板把同批方案拆成 B00 全流程母版、共用骨架和逐变体插拍；收工接片单在撤场前逐条登记实际文件、首选/备选 Take、声音条、连续性异常和缺失项，并独立清点证据全程、细节、空镜、净版、环境声与剪辑余量。主张测试的证据/细节、场景测试的完整证据/空镜/环境声会强制逐版本归档并提供每版独立 Take 栏，候选素材也必须人工选择“可共用/归回版本/补拍”；剪辑装配和成片验收继续负责防串版与三遍观看。只有编号连续、测试变量唯一且固定项一致时四个动作才可使用；工具不读取素材目录、不自动选最佳 Take，也不修改制作状态
- 方案编辑采用 450ms 防抖串行自动保存：快速连续输入只保存最新版本，旧保存完成不会把新编辑误报为“已保存”；项目切换或重新生成前会等待当前保存完成，失败时保留页面内容并取消覆盖操作
- 所有方案输入框共享 `#plan-list` 上的一个事件代理；动态重建方案卡不会重复绑定监听器，字段白名单和当前方案数量会先失败关闭校验，也不会因输入而重建整张卡片。中文输入法组合值先保留在当前输入框，组合结束后才一次性更新方案、保存、刷新提示和播报状态
- 开拍准备、现场监看、拍后快检、盲审与批次工具的逐键派生计算合并到下一动画帧，同一帧内连续输入只刷新一次并读取最终值；方案过期和新方案渲染仍即时生效，已复制成功的盲审或批次反馈不会被排队刷新抹掉
- 复制、开拍清单、导出和各组导演工具都绑定点击时的方案修订；等待剪贴板或本地持久化期间若方案被编辑、过期或替换，旧操作不得把新方案标记为完成，也不得覆盖新反馈。完成凭据通过独立串行控制器同步 Chrome 存储与项目库，旧项目写入晚到时会再以当前状态补偿保存，避免过期完成态复活；两层存储同时失败时只承认内容已经写入剪贴板或文件，并回滚“已完成”。普通编辑的项目清理由现有自动保存合并，不额外逐键保存整个项目。自动保存错误与派生提示错误独立保留，保存成功不会静默吞掉仍存在的界面刷新异常
- 支持复制现场开拍清单与完整方案，以及 Markdown、CSV、JSON 导出
- CSV 导出会把可能被电子表格解释为公式的文本单元格转为安全文本；数值字段保持数值

### 3.1 多项目、版本链与结果回填

- 最多保存 20 个本地项目；切换前会先保存当前创作任务、复盘摘要和方案，并等待已开始的方案保存真正完成；失败时取消切换
- 旧版单工作区自动成为第一个项目；IndexedDB 不可用时安全降级为原有单项目工作区
- 每次新生成方案使用唯一批次时间和测试编号，不再覆盖同主题、同变量的上一轮编号
- 父版本只由编导显式选择；留空表示新的测试起点
- 单项目最多保存 500 个测试版本和 500 条结果记录
- 每个版本的制作状态默认为“未标记”；只有编导在版本卡主动选择后，才会保存待拍、拍摄中、剪辑中、待投放、已上线或已搁置及更新时间
- 生成、复制、导出方案和导入结果都不会自动改变制作状态；清除状态后安全恢复为“未标记”
- 只有人工标记“已上线”且没有结果的版本会进入主动回填提醒；未上线版本仍允许人工补录历史结果，但不会被行动台催回填
- 单版本可直接手动回填；已有结果会预载，避免只补一项指标时误清空其他数据，预览和二次确认后才替换
- 批量结果 CSV / TSV 必须包含“测试编号、消耗”，其余指标可选；未知编号会在预览中列出且默认不写入
- 点击量大于展示量、转化量大于点击量等不可能漏斗会失败关闭；ROI、CTR、CVR 与基础指标计算差异较大时先显示口径提醒，并以固定提醒代码随结果保存
- 同一测试编号再次导入会在二次确认后替换旧结果，原始结果文件和文件名均不保存
- “样本不足、达到目标、高于/低于父版本”等状态是描述性判断，不构成效果预测或因果结论
- 每个版本可保存一条编导人工决策：继续测试、保留方案或停止测试；必须选择主指标、可选护栏指标并填写理由
- 人工决策绑定本地证据指纹；结果重新导入、目标 ROI、最低消耗或版本内容变化后自动标记“需重新确认”
- “实验下一步”只从当前项目已有状态中选择最优先的人工动作；已被有效人工决策确认的样本不足或口径状态不会反复打断用户
- 待办处理完成后，可把证据仍有效的“保留方案”或“继续测试”显式设为下一轮父版本；每个符合条件的版本卡也提供同样快捷入口
- 父版本建议不自动选中、不自动生成方案；“停止测试”和待重审决策永不进入建议
- 支持组合使用结果状态、口径提醒、人工决策、人工制作状态、测试批次和编号/父版本/变量搜索；每页只渲染 20 张卡片，最多 500 个版本均可分页访问
- 每张版本卡提供人工制作状态、结果和决策操作：未上线且无结果时显示“补录结果”，已上线且无结果时显示“回填结果”，已有结果或口径提醒时显示“更新/核对结果”
- 版本卡按摘要、制作、结果、决策渐进展开：待制作默认展开制作，已上线待回填或数据异常展开结果，可复核或失效结论展开决策，已完成或已搁置只显示摘要；用户仍可随时手动展开其他层
- 卡片操作只负责精确载入表单或展开对应区域；结果仍需预览和二次确认，人工决策仍需主动保存，父版本快捷入口只对有效“保留方案”或“继续测试”结论显示
- 有父版本的卡片提供折叠指标对照；只有父子双方均达到各自最低消耗、且都没有指标口径提醒时才计算共同存在的指标，比例差异统一显示为百分点
- 父子对照同时列出当前值、父版本值和消耗参考，只是描述性观察，不构成统计显著性、因果关系或自动胜负判断
- 父子可拍内容 Diff 按“创意语义、测试上下文、生产资料”分组，并列显示父版本和当前版本的钩子、主张、场景、受众、口播、分镜、拍摄任务、剪辑、字幕与合规变化
- 单变量检查允许口播、分镜等随声明变量产生连带改写；若额外改变其他创意语义、基线素材、保持不变项或观察指标，则标记为“需核对”，但不阻止编导查看、编辑或导出
- “实验下一步”会重置遮挡目标的批次与状态条件，再使用目标测试编号精确搜索和定位对应版本；CSV / JSON 台账始终导出当前项目全部版本，不受页面筛选和分页影响，也不包含原始报表和完整拍摄脚本

### 4. 本地素材与工具

- 查看当前浏览器内保存的创作任务、复盘素材数和拍摄方案数
- 用 SHA-256 文件指纹和规范化名称，在团队自有或已授权目录中寻找同源母版
- 区分“指纹完全一致、名称与大小候选、仅名称候选、未找到”
- 所有文件只在本地读取与计算，不上传素材内容
- 单轮最多选择 40 个平台素材和 120 个团队母版；单文件最多 256 MB、合计最多 1 GB，不支持或超限时整轮拒绝
- 匹配过程显示逐文件状态并允许取消；取消或失败不会留下可导出的半成品

### 5. 自有素材局部修复

- 只接受用户自有或已获得明确编辑授权的 PNG、JPEG 与静态 WebP 图片
- 优先提示使用已经找到的自有母版或原始工程；局部修复只作为普通瑕疵处理的补充工具
- 必须再次勾选授权，并由用户使用画笔手动画出 Mask，或用键盘填写百分比矩形选区；没有授权或没有 Mask 时不能处理
- 提供画笔大小、键盘矩形选区、橡皮擦、撤销、重做、清空选区、向内羽化和修复前后对比
- 只修改 Mask 内像素，Mask 外像素保持不变；不自动寻找文字、Logo、水印或品牌标识
- 原图不覆盖；默认保持原尺寸导出，PNG 保留透明通道，JPEG 默认质量为 `0.92`
- 设有文件、尺寸、预计内存、选区比例和绝对选区像素保护，避免侧边栏处理失控

### 6. 素材处理与分析工作台

- 从侧边栏标题下方首屏主入口打开独立全页工作台；“本地素材与工具”仅在空状态保留语境化小入口
- 顶部用素材、处理、转写、分析四步概览复用当前页面状态；唯一主操作会执行真实下一步，分区按钮只作为辅助入口
- 统一显示当前阶段、本轮完成度、下一步原因、可重试错误和交接状态；任务清单导出后自动引导导入本机结果
- 顶部“成果去向”单独说明内容仍仅在本页、可从原文件重建、已经导出、已确认但未交付或已发送；流程进度不会被包装成保存状态
- 草稿下载、人工确认和发送是三个独立事实：未确认草稿即使已经导出也不会显示为审核完成
- 首屏把“分析已有转写”作为推荐快速路径，“处理本地视频”标为需要 FFmpeg / PowerShell 的进阶路径；仍不替用户预选
- 选择已有转写后暂时收起本轮无关的视频与处理区，并把对应概览标为“本轮跳过”；切回视频入口即可恢复，既有页面态不被清空
- 切换入口只改变当前页面引导，不清空已有视频、任务、转写或分析；已有完成状态始终优先保留
- 转写文件、执行结果和会话交接只接受同类最新操作；换文件、重建任务或重置本轮会使旧异步结果失效，避免晚到覆盖
- 未导出的处理/转写任务、仅存在页面内的手动正文、未保存分析或可拍草稿仍存在时，刷新或关闭工作台会触发浏览器原生提醒；空页面、已导出任务和仍可从原文件重建的正文不会误提醒，扩展不会借此自动保存正文或路径
- 宽屏主区最大 1400px；1100px 以下切换顶部导航，720px 以下表单、任务卡和分析结果改为单列
- 只对用户主动选择并确认授权的本地视频生成“标准化 MP4 + 提取 16 kHz 单声道 WAV”任务
- 视频处理的原理说明默认折叠，常用生成、导出和导入动作继续直接显示
- 单批最多 40 个视频、单文件 10 GB、合计 40 GB；不支持或超限文件会失败关闭，原选择与原文件不变
- 可选抖音链接只作为来源备注；“打开原页”以备注旁的弱操作保留，扩展不请求、不解析、不下载链接中的视频
- 可导入本机生成的 TXT、MD、SRT、VTT，或为用户明确配置的本机 `whisper-cli(.exe)` 生成固定参数转写任务
- 所有输入先规范为 Transcript v2；工作台显示来源类型、格式、分段数、时长、解析器版本、本地内容指纹和解析提醒
- SRT / VTT 保留 cue 标签与起止时间，TXT / MD 保留无时间段落来源；时间重叠会提示但不静默修改，手动修改正文会明确作废旧来源映射
- 使用浏览器内确定性规则标注开场钩子、目标受众、问题、核心主张、证据、场景和行动引导
- 分析后必须选择一项改进建议；每份草稿只测试一个主要变量，多变量输入会失败并提示拆分
- 使用本地确定性模板生成完整、可编辑的下一版拍摄任务，并为测试版本与来源分析生成匿名本地编号
- 任何草稿编辑都会撤销确认；只有编导明确确认后，才可发送 V2 交接到当前浏览器会话或导出 V2 JSON
- V1 交接包继续兼容；V2 仍沿用单槽、同包幂等、异包不覆盖和两小时过期规则
- 侧边栏只读预览 V2 草稿，不写入或覆盖已有创作方案；旧四类短建议仍只由用户确认填入空白任务字段

### 7. 本地视频处理

- 仅在用户明确确认“团队自有或已获得转码授权”后生成任务
- 输出固定为 MP4 容器、H.264 视频与 AAC 音频
- 支持均衡、高质量、小体积和指定视频码率预设
- 支持保持原分辨率，或在 1080p / 720p / 480p 边界内等比缩放，不裁剪画面
- 支持保持原帧率，或指定 24 / 25 / 30 / 50 / 60 fps
- 支持音频码率、采样率、输出后缀和 FFmpeg 路径
- 固定保留可复制的元数据与章节，固定不覆盖已有输出文件
- 在独立工作台显示唯一的本地任务队列；导入执行结果后展示完成进度、退出码和失败原因
- 可复制 PowerShell 命令，或导出 JSON 任务清单并使用开源本地执行器
- 自有母版匹配结果可打开同一工作台；受浏览器文件隐私边界限制，用户需要在新标签页重新选择已核对的视频
- 单批最多 40 个视频、单文件 10 GB、合计 40 GB；页面显示每个文件大小、总量、待执行与已导入结果状态

### 8. 版本与更新

- 版本检查、工作区备份、安装回退和隐私边界统一放在素材页底部默认折叠的“维护与隐私”区域，不与日常素材动作争夺视觉注意力
- 显示当前扩展版本和最新稳定 GitHub Release
- 版本检查使用可选权限；只有用户主动检查或明确开启自动检查后才访问 GitHub
- 自动检查最多每天一次，并且只在用户打开侧边栏时运行
- 远端响应只作为版本元数据处理，不下载、不执行、不注入远程代码
- 发现新版本后，必须由用户再次确认才会打开项目 Release 页面
- 支持在更新前导出工作区备份，并在需要时重新导入
- 检查失败时保留当前版本，不修改扩展文件或工作区

```text
→ 展开“批次拍摄与成片交付”，按第 1 步锁定 B00 连续性参照，只拍一次共用骨架，再按场记编号补各变体插条
→ 每个 Take 拍完立即复制对应“拍后快检卡”，人工五查并选择保留、重拍或停机核实；不要等撤场后才发现首帧、证据、连续性或收音问题
→ 拍摄完成、人员和场地尚未撤离时，复制“收工接片单”，逐条填写实际文件、首选/备选 Take 与缺失项；必须补拍的内容当场明确负责人和期限

→ 首轮成片导出后复制“批次成片验收单”；编导先独立验收 B00，再逐条记录时间码并选择通过、返剪或补拍
→ 可选：手动画 Mask 修复自有/授权图片中的小范围普通瑕疵
→ 可选：打开素材处理与分析工作台，处理本地自有视频；明确确认授权，导出任务并在本机 FFmpeg 执行，再导入结果
→ 或直接导入带时间来源的本地转写并分析文案结构
→ 选择一项改进建议，生成、编辑并确认唯一变量的下一版可拍任务草稿
→ 可选：发送 V2 受限交接并打开编导台，或导出 JSON 备用；在侧边栏只读预览草稿，并按需确认填入旧四类空白任务字段
→ 编导手动标记待拍、拍摄中、剪辑中、待投放、已上线或已搁置
→ 标记为待投放后，从“最新批次投放交接”一次复制 B00 → A01 → A02 整批交接包；需要时也可进入版本卡单独复制
→ 可选：展开“灵感接力”，复制不含内部素材和指标数值的脱敏灵感包，或从单张卡复制三路“共创挑战”交给其他编导原创延展
→ 操盘手在平台内人工建计划、设预算并启停；扩展不读取账户、不替代人工投放
→ 已上线后按测试编号快速回填单个结果，或批量导入 CSV / TSV
→ 检查最低消耗、目标 ROI 与父版本描述性对照
→ 按实验下一步行动卡处理口径提醒或记录人工决策
→ 明确采用人工决策建议的父版本，或自行选择新起点，进入下一轮验证
```

V1.4.0 会持久保存侧边栏中的多项目、测试版本、人工制作状态、结果和人工决策记录。顶部“今日编导行动台”根据这些已有记录和当前流程状态临时排序，不保存队列、点击历史、搜索词或自动推断。图片修复与母版匹配只在当前侧边栏会话保留；视频处理队列、转写、分析和可拍任务草稿只在当前独立工作台页面保留。对应页面会在切换或重置前明确提示不可恢复的内容。

### 从 V0.5 迁移

## 更新方式：必须区分安装渠道

### 从 Chrome Web Store 安装

普通 Windows 用户只有通过 Chrome Web Store 安装的正式版本，才能由 Chrome 按商店机制自动更新。扩展开发者不需要、也不应该把签名私钥放入仓库或扩展包。

### 使用“加载已解压的扩展程序”

Chrome 不会自动替换本地源码目录。V1.4.0 的“自动检查”只负责发现新版本并提示，不会伪装成静默安装：

1. 在“本地素材与工具 → 版本与更新”中点击“检查新版本”，或主动开启“打开侧边栏时自动检查”。
2. 首次检查时确认仅访问 `api.github.com` 的可选权限。
3. 发现新版本后，先点击“导出工作区备份”。
4. 点击“确认并打开下载页”，阅读项目 Release 说明并下载源码包。
5. 复制当前扩展目录作为文件备份，再把新版本文件放回原目录。
6. 打开 `chrome://extensions`，在该扩展卡片上点击“重新加载”。
7. 如果新版本无法运行，恢复刚才备份的旧文件，再次点击“重新加载”；需要时导入工作区备份。

保持原扩展目录路径有助于继续使用同一份本地扩展数据。不要把 `.pem` 私钥提交到 GitHub、发送给他人或打包进 Release。

### 企业自托管

Chrome 的自托管扩展更新适用于受企业策略管理的浏览器，不是普通用户“加载已解压”模式的通用替代方案。本项目没有加入会误导用户的 `update_url`。

### 与旧版 douyin-agent 的区别

旧 douyin-agent 的自动切换对象是由本地 Agent 管理的签名知识包：下载后需要验证 HTTPS、SHA-256、Ed25519 签名、版本兼容性和有效期，再原子启用并保留回滚副本。它同样明确要求程序和浏览器扩展使用签名安装包，并没有让“加载已解压”的扩展静默覆盖自身。

当前项目没有常驻本地 Agent，因此只复用其“失败关闭、状态透明、用户确认、保留回退”的原则。完整设计见 [`docs/UPDATE_ARCHITECTURE.md`](docs/UPDATE_ARCHITECTURE.md)。

## 自有素材局部修复工作流

1. 先在“本地素材与工具 → 寻找团队自有或已授权母版”选择平台导出文件与团队自有或已授权目录。
2. 如果找到干净母版或原始工程，优先直接使用母版或重新导出，不做像素修复。
3. 确实只剩普通瑕疵需要处理时，在“自有素材局部修复”中选择自有或授权图片。
4. 勾选“我确认拥有该素材或已取得编辑授权”。
5. 用画笔人工圈选瑕疵；无法使用指针时，可展开“键盘矩形选区”填写 X、Y、宽和高的百分比。两种选区都支持撤销、重做、清空和羽化。
6. 点击“预览局部修复”，拖动对比分界人工检查结果。
7. 选择导出格式并导出新图片。文件名追加 `_repaired`，原始文件不会被覆盖。

局部补全只从 Mask 周围采样普通纹理，并在 Mask 内向内羽化；不会自动检测、定位或识别文字、Logo、品牌标识、平台暗水印、隐藏指纹或溯源标识。单张图片上限为 40 MB、单边 8192 像素、总计 1600 万像素、预计处理内存 256 MB；单次 Mask 还必须同时不超过画面 45% 和 400,000 像素。算法目前在侧边栏主线程同步执行，大图应先从自有工程缩小，或拆成多个小选区分区处理。

## 素材处理与分析工作台工作流

1. 在侧边栏标题下方点击首屏主入口“打开素材处理与分析工作台”。先选择“处理本地视频”或“分析已有转写”。全页工作台顶部会显示统一阶段、素材/处理/转写/分析四步状态与完成度；顶部唯一主操作只在用户点击后执行当前真实下一步。
2. 如果已有本地转写，选择对应入口后直接导入 TXT、MD、SRT、VTT，或点击“直接粘贴转写”聚焦正文区域，然后从下方第 7 步继续；不需要选择视频或填写 FFmpeg 路径。
3. 视频路径中，选择本地自有或授权视频，填写用户自己掌握的原片根目录、输出目录与 FFmpeg 路径，并勾选授权确认。需要调整交付规格时再展开“进阶输出设置”；默认参数可直接使用。
4. 可选填写抖音原页链接作为来源备注。生成任务不会访问该链接；只有用户点击备注旁的“打开原页”时，浏览器才执行一次普通页面导航。
5. 使用顶部主操作生成“标准化 + 音频提取”本地任务，审查并导出 JSON 清单与仓库内置的 `transcode-worker.ps1`；导出后主操作会切换为“导入本机结果”。
6. 在本机运行执行器并导回 results.json。视频标准化和 WAV 音频提取均由本机 FFmpeg 完成；如已安装 whisper.cpp，可生成固定参数的本地转写任务，也可以直接导入已有文本。
7. 对转写正文运行规则型结构分析；JSON、Markdown 等低频格式收在“更多导出”中。需要带回编导决策台时，使用顶部主操作或“发送并打开编导台”。同一分析重复点击不会重复排队；若收件箱已有不同结果则不会覆盖，顶部会切换为处理冲突的入口。
8. 侧边栏在工作区恢复后读取当前会话收件箱并显示预览；若已有不同 JSON 或会话预览，只提示“另有待确认结果”，由用户主动切换。勾选需要的空白字段再确认；已有内容始终跳过。Chrome 114/115 或浏览器拒绝自动打开时，结果仍会排队，请点击扩展图标。也可使用“导出 JSON 交接包”完成原有手动流程。

Chrome 扩展不能在未安装 Native Messaging Host 的情况下直接启动 FFmpeg 或 whisper.cpp。因此这里的“一键”指一次生成一组受限、可审查的本地任务，并不代表扩展会静默执行本机程序。项目不包含云端转写回退，也不会把视频、音频或转写文本发送到远程服务。

素材处理与分析工作台不提供“抖音链接无水印下载”、媒体地址解析、平台请求拦截或平台标识处理。来源链接不会进入 FFmpeg 或 whisper.cpp 参数，只会作为可选备注写入用户主动导出的任务清单；该清单含本机路径和可能的来源 URL，应只保存在可信设备。

## 本地视频标准化与转写准备

Chrome 扩展页面不能直接启动任意本机程序。若要让扩展直接调用 FFmpeg，必须另外安装并注册 Native Messaging Host，同时为扩展增加 `nativeMessaging` 权限。为保持当前开源扩展的最小权限和可审查性，V1.4.0 不静默安装本地服务，也不申请该权限；纯 WebCodecs 只提供底层编解码块，仍需另行完成输入解封装、音视频同步和 MP4 封装，无法在不同浏览器环境中可靠替代完整 FFmpeg。相关能力边界可参考 Chrome 的 [Native Messaging](https://developer.chrome.com/docs/extensions/develop/concepts/native-messaging) 与 [WebCodecs 视频处理说明](https://developer.chrome.com/docs/web-platform/best-practices/webcodecs)。

V1.4.0 已把侧边栏中的重复转码队列合并进独立工作台。侧边栏只保留入口，标准化视频、提取分析音频、进阶输出设置与执行结果导入共用一套状态，避免两处参数不一致。浏览器不会跨标签传递本地文件选择，因此从母版匹配结果打开工作台后需要重新选择已核对的文件。

当前采用可审计的本地任务模式，单批最多 40 个视频、单文件 10 GB、合计 40 GB：

1. 从侧边栏首屏或“本地素材与工具 → 视频处理已移入独立工作台”打开工作台，选择“处理本地视频”，再选择团队自有或已授权原片。
2. 勾选授权确认，并填写浏览器无法读取的原片根目录与输出目录。
3. 默认直接使用均衡预设；如确有交付要求，再展开“进阶输出设置”，选择编码预设、分辨率、帧率、视频码率、音频码率、采样率与输出后缀。这里的参数只影响标准化 MP4，分析用 WAV 始终固定为 PCM 16-bit、16 kHz、单声道。
4. 生成任务后，检查每条输入、输出和完整 PowerShell 命令。
5. 导出 `qianchuan-material-analysis-tasks.json`，并下载项目内的 `transcode-worker.ps1`。
6. 确保本机已安装 FFmpeg。将两个文件放在同一目录，在该目录打开 PowerShell：

```powershell
powershell -NoProfile -File .\transcode-worker.ps1 -ManifestPath .\qianchuan-material-analysis-tasks.json
```

如 FFmpeg 不在系统 PATH，可显式指定路径；开源项目不会硬编码任何用户的绝对路径：

```powershell
powershell -NoProfile -File .\transcode-worker.ps1 `
  -ManifestPath .\qianchuan-material-analysis-tasks.json `
  -FfmpegPath "C:\tools\ffmpeg\bin\ffmpeg.exe"
```

执行器逐项处理并持续写入 `qianchuan-material-analysis-tasks.results.json`。将该结果文件导回工作台，即可查看成功数量、失败任务和具体原因。执行器不会发起网络请求，不会覆盖已有输出，不会删除原片。

每条任务固定包含：

```text
-map_metadata 0 -map_chapters 0
```

这会尽可能把输入中可由目标 MP4 表示的元数据与章节复制到输出。不同容器支持的字段并不完全相同，因此不能保证所有私有字段都可无损迁移。项目不提供清元数据、裁剪、模糊、去标识、自定义滤镜或暗水印相关选项，也不声称转码会移除任何标记。

## 规则说明

V1.4.0 使用可审查的本地规则和确定性草稿模板，不依赖远程模型：

- 以非零消耗中位数作为基础样本门槛
- 同时参考展示量、CTR 中位数、CVR 中位数和目标 ROI
- 低样本素材只标记为“待验证”，不会直接认定为失败
- 策略先选择历史表现较好的素材作为基线
- 同一批方案只改变用户选择的一个变量
- 文案与生产资料只使用可选创作任务、历史标签和合规模板组合生成
- 独立工作台的 SRT / VTT 解析保留 cue 时间与标签；TXT / MD 使用空时间段落，编辑正文后不沿用旧映射
- 可拍草稿只根据当前结构分析、用户选择的唯一变量和固定模板生成，不把规则输出描述成真实效果预测

这些结论用于辅助编导决策，不等同于因果证明。正式投放前仍需由编导、投手与合规负责人复核事实证据、样本量和平台规则。

## 隐私与安全边界

- 当前项目工作区保存在 `chrome.storage.local`；项目集合、测试版本与结果记录保存在同一扩展来源的 IndexedDB。两者都只存在于当前浏览器资料目录。
- 原始 CSV、视频、图片和母版文件不会上传，也不会自动写入磁盘。
- 图片局部修复只在浏览器当前页面内处理；只修改手动画出的 Mask，并始终导出新文件。
- 素材处理与分析工作台只读取用户主动选择的视频与文本；抖音链接只作备注或用户确认后的原页导航，不用于抓取媒体。
- 本地转写只支持导入文本或生成受限的本机 whisper.cpp 任务，不调用浏览器语音识别或云端转写服务。
- 分析交接包最大 128 KB。V1 仍只包含固定摘要、结构覆盖、缺项建议和四类短文本建议；V2 另含最大 48 KB 的固定白名单可拍草稿。两版均不包含原始全文、来源文件名、视频、账号数据或本机路径，侧边栏拒绝未知字段、错误来源、篡改标识和活动内容。
- 一键交接必须先由编导明确确认当前草稿，且只写入当前浏览器的 `chrome.storage.session` 单槽，不进入长期工作区备份；两小时过期，坏数据或过期数据失败关闭并清理。侧边栏仅只读展示 V2 草稿，不写入创作方案；应用旧四类空白建议或用户明确清除后才消费该槽。
- 方案卡“片场执行条”和“本条开拍单”只读取当前本地方案；缺项或方案过期时禁止复制。成功复制只写入用户剪贴板，不标记方案完成、不修改制作状态、不上传内容，也不读取平台数据。
- “拍后快检卡”只把当前方案重排为人工回看模板；不读取或识别真实图片、视频和声音，不自动评分或选 Take，不保存文件名、时间码、勾选和结论，也不修改方案、接片映射或制作状态。
- 扩展不读取千川账号密码，不注入千川页面，不拦截平台网络请求。
- 扩展不包含远程托管代码。
- Manifest V3 扩展页显式使用 `script-src 'self'; object-src 'none';`，只允许仓库内脚本执行。
- 非媒体导入统一限制为：报表 8 MB、全部项目工作区备份 12 MB、测试结果 2 MB / 1,000 行、本机执行结果 2 MB、转写文本 4 MB、分析交接包 128 KB；格式、结构、漏斗校验或解析失败时保留当前状态。
- 版本检查只在用户主动触发或明确开启自动检查后，向 GitHub API 请求本项目公开 Release 元数据；不会发送创作任务、报表、脚本或素材。
- GitHub API 访问是可选主机权限；未授权时不会发起检查。
- 母版匹配只帮助团队寻找自有或已获得明确授权的源文件。
- 转码只对用户主动选择并确认拥有或获授权的原片生成本地任务；视频内容不离开设备。
- 转码任务清单包含用户填写的本地输入与输出路径，只应保存在可信设备上。
- 转码固定保留可复制元数据与章节，不提供清元数据、裁剪、模糊或自定义滤镜。
- 不提供暗水印检测、定位、移除、破解、规避或平台风控绕过功能。

需要干净素材时，应回到团队自有原片、原始工程或已授权素材重新导出。详见 [`PRIVACY.md`](PRIVACY.md)。

## 本地开发与验证

项目不依赖构建工具或远程脚本，源码可以直接作为未打包扩展加载。运行时唯一第三方库是固定在仓库内的 `idb 8.0.3`（ISC，约 8 KB 未压缩），用于把 IndexedDB 请求转换为 Promise；扩展不会从 CDN 下载它。许可证见 [`vendor/idb.LICENSE.txt`](vendor/idb.LICENSE.txt)。

```powershell
npm test
```

## 尚未实现与后续探索

- V1.3 只支持用户主动手动回填或导入结果 CSV / TSV，不读取千川页面、账号或网络请求，也不自动同步平台投放结果。
- 版本状态目前是可筛选、可搜索、可分页的文本时间线，没有趋势图、版本归档、多人协作或云同步。
- 结果对照不做统计显著性检验，不自动宣布“胜负”，也不会据此自动生成或发布下一版素材。
- 浏览器内不会直接启动 FFmpeg 或 whisper.cpp；是否引入独立签名本地 Runner 仅作为后续探索，不构成承诺。
- 当前版本没有页面读取、内容脚本、平台请求拦截或自动执行页面操作的权限，也不把这些能力描述为 V1 已有功能。
- 单条与整批投放交接都只是用户主动复制的本地文本，不创建千川广告计划、不设置或修改预算、不自动启停、不读取账户，也不确认平台实际执行结果。
- 灵感接力与共创挑战使用固定本地规则，不调用生成式远程模型，不训练个性化模型，不保存复制记录，也不会自动生成可直接发布的品牌脚本。共创挑战只接受已脱敏的机制、证据代码并重新查固定文案，忽略卡片自由文本，避免被篡改字段带出内部素材。

北极星指标：**上线素材中，同时达到目标消耗和目标 ROI 的素材占比。**
