# 抖音千川素材编导 Agent

专门给抖音千川素材编导使用的开源 Chrome / Edge 本地扩展。它保留用于快速复盘与下一版决策的侧边栏编导工作区，同时提供独立的全页“素材处理与分析工作台”。

它把可选创作任务、历史素材复盘、单变量测试策略和拍摄生产资料放进同一个本地工作区。编导无需先填写商业资料；导入千川素材报表后，即可得到下一版素材的测试假设、口播稿、分镜、拍摄任务单、剪辑要求、字幕重点与合规检查。

> 核心目标不是“多生成几条通用文案”，而是帮助编导基于历史证据决定下一批拍什么、只改什么、如何验证。

## V1.1.0 能做什么

首次打开会显示可收起、可重新打开的三步引导：“导入历史报表 → 完成素材复盘 → 生成并导出任务”。侧边栏顶部同时显示核心进度和唯一下一步操作。创作任务始终是可选上下文；系统会用规范化后的字段映射、复盘排名、标签、ROI、创作任务、测试变量和最低消耗生成依赖指纹，其中任一项变化都会让旧方案明确失效。V0.6.1 及更早方案没有该指纹，恢复后会安全降级为“需要重新生成”，不会崩溃或继续导出。

V1.1.0 把独立工作台从“结构分析”继续闭环到“下一版可拍任务”。SRT / VTT 导入会保留每个 cue 的开始时间、结束时间、标签和正文，TXT / MD 使用无时间的段落来源；用户手动编辑正文后，旧时间或段落映射会立即明确失效。分析结果会显示来源，并要求先选择一项改进建议，再围绕唯一主要变量生成可编辑草稿。

草稿包含本地唯一测试编号、父版本、匿名来源分析编号、问题摘要、测试假设、保持不变项、前三秒钩子、口播稿、分镜、补拍镜头、字幕重点、剪辑节奏、成功指标和停止条件。生成器是本地确定性模板，不预测投放效果；事实、证据、合规表达和指标阈值必须由编导人工核对。任何编辑都会撤销旧确认，只有重新明确确认后才能发送 V2 会话交接或导出 V2 交接包。

V1.1.0 同时保留完整会话生命周期。首屏始终显示低强调的“开始新一轮 / 重置本轮”；当本页已有视频、路径与授权参数、处理或转写任务、正文、分析、草稿、交接状态或错误时，必须先确认才会重置。确认文案会特别指出尚未导出的任务、分析和草稿；取消时不改变任何内容。确认后只复位当前工作台页面内存和界面，绝不会删除原片、已下载文件、侧边栏内容、`chrome.storage.local` 工作区或已经发送到会话收件箱的结果。

V1.0.6 在独立工作台首屏提供“处理本地视频”和“分析已有转写”两个入口，不再默认把所有用户引向视频选择。选择已有转写后，顶部唯一主操作会直接打开本地 TXT、MD、SRT 或 VTT，也可以从首屏聚焦正文粘贴区；不要求先授权视频或生成 FFmpeg 任务。入口只存在于当前页面内存，切换时会保留并提示已有视频选择、任务、正文和分析结果，不新增持久化记录。

V1.0.5 将独立工作台收口为一条由顶部唯一主操作驱动的流程。按钮不再只负责滚动定位，而会根据真实状态依次选择素材、补齐校验、生成任务、导出清单、导入本机结果、导入转写、分析结构并发送编导台。首屏同时显示统一阶段、四步状态、完成度、下一步原因和集中错误；分区按钮仍作为辅助入口保留。所有动作仍由用户逐次点击，不会自动启动本机程序或绕过授权与文件校验。

V1.0.5 延续 V1.0.4 的可审查交接链路：工作台可把固定 schema 的结果一键放入 `chrome.storage.session` 单槽收件箱并尝试打开侧边栏，也继续提供本地 JSON 备用。会话结果两小时后失效；同一分析重复发送保持幂等，不同待处理结果不会被静默覆盖。侧边栏先校验和预览，再由用户勾选并确认填入空白的“目标受众、受众问题、核心主张、可用证据”。它不会自动覆盖已有任务内容，不包含原始转写全文、文件名、视频信息或本机路径，也不会把确定性规则描述成投放效果预测。

V1.0.5 延续 V1.0.2 的首屏工作台入口、最近任务继续卡和逐键工作区恢复：单条损坏记录不会阻止页面启动；界面会列出具体异常键，只有用户显式点击并再次确认后才清理。读取或保存失败时，当前会话仍可继续导出，且不会自动删除其他正常数据。

### 1. 创作任务（可选）

- 记录素材主题、目标受众、创作目标、受众问题、核心主张与可用证据
- 记录拍摄条件、风险备注和目标视频时长
- 提供效果验证、场景共鸣与人物故事三种通用起步模板
- 所有字段均为可选；不填写主题也能复盘和生成下一版任务
- 自动保存在当前浏览器的本地存储中

### 2. 素材复盘

- 导入 UTF-8 CSV / TSV 报表
- 报表最大 8 MB、50,000 行和 200 列；未闭合引号、空白或重复表头会在分析前拒绝
- 预览前 5 行，避免导错文件
- 自动识别常见千川字段别名，并允许手动调整字段映射
- 明确提示缺失的必需字段和可选指标
- 在分析前补齐或修改人群、前三秒钩子、核心主张、拍摄场景标签
- 结合样本量、消耗、CTR、CVR 和目标 ROI 输出诊断与置信度
- 导出复盘 JSON 或 Markdown

### 3. 下一版任务

- 从表现较好的历史素材中选择基线
- 每轮只测试一个变量：钩子、核心主张、场景或受众
- 每个方案包含测试假设、基线、唯一变量、保持不变项、观察指标、最低测试消耗、停止条件和成功后动作
- 根据可选创作任务与历史基线生成可编辑的口播稿、镜头级分镜、拍摄任务单、剪辑要求、字幕重点和合规清单
- 自动保存编辑结果
- 支持一键复制，以及 Markdown、CSV、JSON 导出
- CSV 导出会把可能被电子表格解释为公式的文本单元格转为安全文本；数值字段保持数值

### 4. 本地素材与工具

- 查看当前浏览器内保存的创作任务、复盘素材数和拍摄方案数
- 用 SHA-256 文件指纹和规范化名称，在团队自有或已授权目录中寻找同源母版
- 区分“指纹完全一致、名称与大小候选、仅名称候选、未找到”
- 所有文件只在本地读取与计算，不上传素材内容
- 单轮最多选择 40 个平台素材和 120 个团队母版；单文件最多 256 MB、合计最多 1 GB，不支持或超限时整轮拒绝
- 匹配过程显示逐文件状态并允许取消；取消或失败不会留下可导出的半成品

### 5. 自有素材局部修复

- 只接受用户自有或已获得明确编辑授权的 PNG、JPEG 与静态 WebP 图片
- 优先提示使用已经找到的自有母版或原始工程；局部修复只作为普通瑕疵处理的补充工具
- 必须再次勾选授权，并由用户使用画笔手动画出 Mask，或用键盘填写百分比矩形选区；没有授权或没有 Mask 时不能处理
- 提供画笔大小、键盘矩形选区、橡皮擦、撤销、重做、清空选区、向内羽化和修复前后对比
- 只修改 Mask 内像素，Mask 外像素保持不变；不自动寻找文字、Logo、水印或品牌标识
- 原图不覆盖；默认保持原尺寸导出，PNG 保留透明通道，JPEG 默认质量为 `0.92`
- 设有文件、尺寸、预计内存、选区比例和绝对选区像素保护，避免侧边栏处理失控

### 6. 素材处理与分析工作台

- 从侧边栏标题下方首屏主入口打开独立全页工作台；“本地素材与工具”仅在空状态保留语境化小入口
- 顶部用素材、处理、转写、分析四步概览复用当前页面状态；唯一主操作会执行真实下一步，分区按钮只作为辅助入口
- 统一显示当前阶段、本轮完成度、下一步原因、可重试错误和交接状态；任务清单导出后自动引导导入本机结果
- 首屏可选择“处理本地视频”或“分析已有转写”；后者可直接导入文本或聚焦粘贴区，不强迫先选视频
- 切换入口只改变当前页面引导，不清空已有视频、任务、转写或分析；已有完成状态始终优先保留
- 宽屏主区最大 1400px；1100px 以下切换顶部导航，720px 以下表单、任务卡和分析结果改为单列
- 只对用户主动选择并确认授权的本地视频生成“标准化 MP4 + 提取 16 kHz 单声道 WAV”任务
- 单批最多 40 个视频、单文件 10 GB、合计 40 GB；不支持或超限文件会失败关闭，原选择与原文件不变
- 可选抖音链接只作为来源备注，或在用户点击后打开原页；扩展不请求、不解析、不下载链接中的视频
- 可导入本机生成的 TXT、MD、SRT、VTT，或为用户明确配置的本机 `whisper-cli(.exe)` 生成固定参数转写任务
- SRT / VTT 保留 cue 标签与起止时间，TXT / MD 保留无时间段落来源；手动修改正文会明确作废旧来源映射
- 使用浏览器内确定性规则标注开场钩子、目标受众、问题、核心主张、证据、场景和行动引导
- 分析后必须选择一项改进建议；每份草稿只测试一个主要变量，多变量输入会失败并提示拆分
- 使用本地确定性模板生成完整、可编辑的下一版拍摄任务，并为测试版本与来源分析生成匿名本地编号
- 任何草稿编辑都会撤销确认；只有编导明确确认后，才可发送 V2 交接到当前浏览器会话或导出 V2 JSON
- V1 交接包继续兼容；V2 仍沿用单槽、同包幂等、异包不覆盖和两小时过期规则
- 侧边栏只读预览 V2 草稿，不写入或覆盖已有创作方案；旧四类短建议仍只由用户确认填入空白任务字段

### 7. 自有母版转码

- 仅在用户明确确认“团队自有或已获得转码授权”后生成任务
- 输出固定为 MP4 容器、H.264 视频与 AAC 音频
- 支持均衡、高质量、小体积和指定视频码率预设
- 支持保持原分辨率，或在 1080p / 720p / 480p 边界内等比缩放，不裁剪画面
- 支持保持原帧率，或指定 24 / 25 / 30 / 50 / 60 fps
- 支持音频码率、采样率、输出后缀和 FFmpeg 路径
- 固定保留可复制的元数据与章节，固定不覆盖已有输出文件
- 显示本地任务队列；导入执行结果后展示完成进度、退出码和失败原因
- 可复制 PowerShell 命令，或导出 JSON 任务清单并使用开源本地执行器
- 从自有母版匹配结果一键将候选视频加入转码队列
- 单批最多 100 个视频、单文件 20 GB、合计 100 GB；页面显示每个文件大小、总量、待执行与已导入结果状态

### 8. 版本与更新

- 显示当前扩展版本和最新稳定 GitHub Release
- 版本检查使用可选权限；只有用户主动检查或明确开启自动检查后才访问 GitHub
- 自动检查最多每天一次，并且只在用户打开侧边栏时运行
- 远端响应只作为版本元数据处理，不下载、不执行、不注入远程代码
- 发现新版本后，必须由用户再次确认才会打开项目 Release 页面
- 支持在更新前导出工作区备份，并在需要时重新导入
- 检查失败时保留当前版本，不修改扩展文件或工作区

## 标准工作流

```text
可选：填写并保存创作任务
→ 导入千川素材报表（也可以从这里直接开始）
→ 检查字段映射与数据预览
→ 补齐素材标签
→ 完成历史素材复盘
→ 选择本轮唯一变量与最低测试消耗
→ 生成并编辑策略、脚本、分镜和拍摄任务
→ 导出给编导、拍摄和剪辑执行
→ 可选：从自有母版匹配结果加入本地转码队列
→ 明确确认授权，导出任务并在本机 FFmpeg 执行
→ 导入执行结果，查看完成进度和失败原因
→ 可选：手动画 Mask 修复自有/授权图片中的小范围普通瑕疵
→ 可选：打开素材处理与分析工作台，处理本地自有视频、导入带时间来源的本地转写并分析文案结构
→ 选择一项改进建议，生成、编辑并确认唯一变量的下一版可拍任务草稿
→ 可选：发送 V2 受限交接并打开编导台，或导出 JSON 备用；在侧边栏只读预览草稿，并按需确认填入旧四类空白任务字段
→ 上线后重新导入结果，进入下一轮验证
```

V1.1.0 仍只保存最近一个编导项目。顶部“最近任务”会根据当前浏览器已有的创作任务、复盘、下一版方案和导出状态，将用户送到可靠的继续位置；它不新增时间线或任务历史。多项目、脚本版本与投放结果自动回填尚未实现。图片修复、母版匹配、转码、独立工作台分析和可拍任务草稿只在当前页面会话中保留；独立工作台入口选择同样不会持久化，并会明确提示刷新或关闭后不能恢复视频选择、处理队列、转写正文或草稿。会话交接仅临时保存受限建议和白名单草稿，用户主动导出的任务清单与 JSON 交接包由用户自行管理。

### 从 V0.5 迁移

V1.1.0 继续兼容 V0.5 的 `productBrief` 与 schema 1 备份，也可读取 V0.6 使用的 schema 2 工作区备份；备份 schema 没有为了版本号无必要升级。旧字段会一次性映射为 `creativeTask`：名称作为可选素材主题，受众、问题、主张、证据、时长和拍摄条件继续保留。只有新记录成功写回后才清理旧存储键；损坏的旧记录不会自动删除，必须由用户在恢复面板确认。旧版备份文件本身不会被修改。

## 安装

1. 下载或克隆本仓库。
2. 打开 Chrome 的 `chrome://extensions`，或 Edge 的 `edge://extensions`。
3. 开启“开发者模式”。
4. 点击“加载已解压的扩展程序”。
5. 选择本仓库根目录，即包含 `manifest.json` 的文件夹。
6. 点击扩展图标，在浏览器侧边栏中打开工作台。

扩展使用 Manifest V3，需要 Chrome 114+ 或对应版本的 Chromium Edge。

## 更新方式：必须区分安装渠道

### 从 Chrome Web Store 安装

普通 Windows 用户只有通过 Chrome Web Store 安装的正式版本，才能由 Chrome 按商店机制自动更新。扩展开发者不需要、也不应该把签名私钥放入仓库或扩展包。

### 使用“加载已解压的扩展程序”

Chrome 不会自动替换本地源码目录。V1.1.0 的“自动检查”只负责发现新版本并提示，不会伪装成静默安装：

1. 在“本地素材与工具 → 版本与更新”中点击“检查新版本”，或主动开启“打开侧边栏时自动检查”。
2. 首次检查时确认仅访问 `api.github.com` 的可选权限。
3. 发现新版本后，先点击“导出工作区备份”。
4. 点击“确认并打开下载页”，阅读项目 Release 说明并下载源码包。
5. 复制当前扩展目录作为文件备份，再把新版本文件放回原目录。
6. 打开 `chrome://extensions`，在该扩展卡片上点击“重新加载”。
7. 如果新版本无法运行，恢复刚才备份的旧文件，再次点击“重新加载”；需要时导入工作区备份。

保持原扩展目录路径有助于继续使用同一份本地扩展数据。不要把 `.pem` 私钥提交到 GitHub、发送给他人或打包进 Release。

### 企业自托管

Chrome 的自托管扩展更新适用于受企业策略管理的浏览器，不是普通用户“加载已解压”模式的通用替代方案。本项目没有加入会误导用户的 `update_url`。

### 与旧版 douyin-agent 的区别

旧 douyin-agent 的自动切换对象是由本地 Agent 管理的签名知识包：下载后需要验证 HTTPS、SHA-256、Ed25519 签名、版本兼容性和有效期，再原子启用并保留回滚副本。它同样明确要求程序和浏览器扩展使用签名安装包，并没有让“加载已解压”的扩展静默覆盖自身。

当前项目没有常驻本地 Agent，因此只复用其“失败关闭、状态透明、用户确认、保留回退”的原则。完整设计见 [`docs/UPDATE_ARCHITECTURE.md`](docs/UPDATE_ARCHITECTURE.md)。

## 自有素材局部修复工作流

1. 先在“本地素材与工具 → 寻找团队自有或已授权母版”选择平台导出文件与团队自有或已授权目录。
2. 如果找到干净母版或原始工程，优先直接使用母版或重新导出，不做像素修复。
3. 确实只剩普通瑕疵需要处理时，在“自有素材局部修复”中选择自有或授权图片。
4. 勾选“我确认拥有该素材或已取得编辑授权”。
5. 用画笔人工圈选瑕疵；无法使用指针时，可展开“键盘矩形选区”填写 X、Y、宽和高的百分比。两种选区都支持撤销、重做、清空和羽化。
6. 点击“预览局部修复”，拖动对比分界人工检查结果。
7. 选择导出格式并导出新图片。文件名追加 `_repaired`，原始文件不会被覆盖。

局部补全只从 Mask 周围采样普通纹理，并在 Mask 内向内羽化；不会自动检测、定位或识别文字、Logo、品牌标识、平台暗水印、隐藏指纹或溯源标识。单张图片上限为 40 MB、单边 8192 像素、总计 1600 万像素、预计处理内存 256 MB；单次 Mask 还必须同时不超过画面 45% 和 400,000 像素。算法目前在侧边栏主线程同步执行，大图应先从自有工程缩小，或拆成多个小选区分区处理。

## 素材处理与分析工作台工作流

1. 在侧边栏标题下方点击首屏主入口“打开素材处理与分析工作台”。先选择“处理本地视频”或“分析已有转写”。全页工作台顶部会显示统一阶段、素材/处理/转写/分析四步状态与完成度；顶部唯一主操作只在用户点击后执行当前真实下一步。
2. 如果已有本地转写，选择对应入口后直接导入 TXT、MD、SRT、VTT，或点击“直接粘贴转写”聚焦正文区域，然后从下方第 7 步继续；不需要选择视频或填写 FFmpeg 路径。
3. 视频路径中，选择本地自有或授权视频，填写用户自己掌握的原片根目录、输出目录与 FFmpeg 路径，并勾选授权确认。
4. 可选填写抖音原页链接作为来源备注。生成任务不会访问该链接；只有用户点击“只打开原页”时，浏览器才执行一次普通页面导航。
5. 使用顶部主操作生成“标准化 + 音频提取”本地任务，审查并导出 JSON 清单与仓库内置的 `transcode-worker.ps1`；导出后主操作会切换为“导入本机结果”。
6. 在本机运行执行器并导回 results.json。视频标准化和 WAV 音频提取均由本机 FFmpeg 完成；如已安装 whisper.cpp，可生成固定参数的本地转写任务，也可以直接导入已有文本。
7. 对转写正文运行规则型结构分析，并导出 JSON 或 Markdown；需要带回编导决策台时，使用顶部主操作或辅助按钮“发送并打开编导台”。同一分析重复点击不会重复排队；若收件箱已有不同结果则不会覆盖，顶部会切换为处理冲突的入口。
8. 侧边栏在工作区恢复后读取当前会话收件箱并显示预览；若已有不同 JSON 或会话预览，只提示“另有待确认结果”，由用户主动切换。勾选需要的空白字段再确认；已有内容始终跳过。Chrome 114/115 或浏览器拒绝自动打开时，结果仍会排队，请点击扩展图标。也可使用“导出 JSON 交接包”完成原有手动流程。

Chrome 扩展不能在未安装 Native Messaging Host 的情况下直接启动 FFmpeg 或 whisper.cpp。因此这里的“一键”指一次生成一组受限、可审查的本地任务，并不代表扩展会静默执行本机程序。项目不包含云端转写回退，也不会把视频、音频或转写文本发送到远程服务。

素材处理与分析工作台不提供“抖音链接无水印下载”、媒体地址解析、平台请求拦截或平台标识处理。来源链接不会进入 FFmpeg 或 whisper.cpp 参数，只会作为可选备注写入用户主动导出的任务清单；该清单含本机路径和可能的来源 URL，应只保存在可信设备。

## 自有母版转码工作流

Chrome 扩展页面不能直接启动任意本机程序。若要让扩展直接调用 FFmpeg，必须另外安装并注册 Native Messaging Host，同时为扩展增加 `nativeMessaging` 权限。为保持当前开源扩展的最小权限和可审查性，V1.1.0 不静默安装本地服务，也不申请该权限；纯 WebCodecs 只提供底层编解码块，仍需另行完成输入解封装、音视频同步和 MP4 封装，无法在不同浏览器环境中可靠替代完整 FFmpeg。相关能力边界可参考 Chrome 的 [Native Messaging](https://developer.chrome.com/docs/extensions/develop/concepts/native-messaging) 与 [WebCodecs 视频处理说明](https://developer.chrome.com/docs/web-platform/best-practices/webcodecs)。

当前采用可审计的本地任务模式：

1. 在“本地素材与工具 → 团队母版转码”中选择团队自有或已授权原片。
2. 勾选授权确认，并填写浏览器无法读取的原片根目录与输出目录。
3. 选择编码预设、分辨率、帧率、视频质量或码率、音频码率与采样率。
4. 生成任务后，检查每条输入、输出和完整 PowerShell 命令。
5. 导出 `qianchuan-transcode-tasks.json`，并下载项目内的 `transcode-worker.ps1`。
6. 确保本机已安装 FFmpeg。将两个文件放在同一目录，在该目录打开 PowerShell：

```powershell
powershell -NoProfile -File .\transcode-worker.ps1 -ManifestPath .\qianchuan-transcode-tasks.json
```

如 FFmpeg 不在系统 PATH，可显式指定路径；开源项目不会硬编码任何用户的绝对路径：

```powershell
powershell -NoProfile -File .\transcode-worker.ps1 `
  -ManifestPath .\qianchuan-transcode-tasks.json `
  -FfmpegPath "C:\tools\ffmpeg\bin\ffmpeg.exe"
```

执行器逐项处理并持续写入 `qianchuan-transcode-tasks.results.json`。将该结果文件导回扩展，即可查看成功数量、失败任务和具体原因。执行器不会发起网络请求，不会覆盖已有输出，不会删除原片。

每条任务固定包含：

```text
-map_metadata 0 -map_chapters 0
```

这会尽可能把输入中可由目标 MP4 表示的元数据与章节复制到输出。不同容器支持的字段并不完全相同，因此不能保证所有私有字段都可无损迁移。项目不提供清元数据、裁剪、模糊、去标识、自定义滤镜或暗水印相关选项，也不声称转码会移除任何标记。

| 支付 ROI | 支付ROI、整体支付ROI、ROI、ROAS | 否 |

## 规则说明

V1.1.0 使用可审查的本地规则和确定性草稿模板，不依赖远程模型：

- 以非零消耗中位数作为基础样本门槛
- 同时参考展示量、CTR 中位数、CVR 中位数和目标 ROI
- 低样本素材只标记为“待验证”，不会直接认定为失败
- 策略先选择历史表现较好的素材作为基线
- 同一批方案只改变用户选择的一个变量
- 文案与生产资料只使用可选创作任务、历史标签和合规模板组合生成
- 独立工作台的 SRT / VTT 解析保留 cue 时间与标签；TXT / MD 使用空时间段落，编辑正文后不沿用旧映射
- 可拍草稿只根据当前结构分析、用户选择的唯一变量和固定模板生成，不把规则输出描述成真实效果预测

这些结论用于辅助编导决策，不等同于因果证明。正式投放前仍需由编导、投手与合规负责人复核事实证据、样本量和平台规则。

## 隐私与安全边界

- 创作任务、复盘摘要、策略与编辑内容只保存在当前浏览器的 `chrome.storage.local`。
- 原始 CSV、视频、图片和母版文件不会上传，也不会自动写入磁盘。
- 图片局部修复只在浏览器当前页面内处理；只修改手动画出的 Mask，并始终导出新文件。
- 素材处理与分析工作台只读取用户主动选择的视频与文本；抖音链接只作备注或用户确认后的原页导航，不用于抓取媒体。
- 本地转写只支持导入文本或生成受限的本机 whisper.cpp 任务，不调用浏览器语音识别或云端转写服务。
- 分析交接包最大 128 KB。V1 仍只包含固定摘要、结构覆盖、缺项建议和四类短文本建议；V2 另含最大 48 KB 的固定白名单可拍草稿。两版均不包含原始全文、来源文件名、视频、账号数据或本机路径，侧边栏拒绝未知字段、错误来源、篡改标识和活动内容。
- 一键交接必须先由编导明确确认当前草稿，且只写入当前浏览器的 `chrome.storage.session` 单槽，不进入长期工作区备份；两小时过期，坏数据或过期数据失败关闭并清理。侧边栏仅只读展示 V2 草稿，不写入创作方案；应用旧四类空白建议或用户明确清除后才消费该槽。
- 扩展不读取千川账号密码，不注入千川页面，不拦截平台网络请求。
- 扩展不包含远程托管代码。
- Manifest V3 扩展页显式使用 `script-src 'self'; object-src 'none';`，只允许仓库内脚本执行。
- 非媒体导入统一限制为：报表 8 MB、工作区备份 2 MB、本机执行结果 2 MB、转写文本 4 MB、分析交接包 128 KB；格式、结构或解析失败时保留当前状态。
- 版本检查只在用户主动触发或明确开启自动检查后，向 GitHub API 请求本项目公开 Release 元数据；不会发送创作任务、报表、脚本或素材。
- GitHub API 访问是可选主机权限；未授权时不会发起检查。
- 母版匹配只帮助团队寻找自有或已获得明确授权的源文件。
- 转码只对用户主动选择并确认拥有或获授权的原片生成本地任务；视频内容不离开设备。
- 转码任务清单包含用户填写的本地输入与输出路径，只应保存在可信设备上。
- 转码固定保留可复制元数据与章节，不提供清元数据、裁剪、模糊或自定义滤镜。
- 不提供暗水印检测、定位、移除、破解、规避或平台风控绕过功能。

需要干净素材时，应回到团队自有原片、原始工程或已授权素材重新导出。详见 [`PRIVACY.md`](PRIVACY.md)。
