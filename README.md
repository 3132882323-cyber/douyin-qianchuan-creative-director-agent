# 抖音千川素材编导 Agent

专门给抖音千川素材编导使用的开源 Chrome / Edge 侧边栏扩展。

它把商品 Brief、历史素材复盘、单变量测试策略和拍摄生产资料放进同一个本地工作区。编导导入千川素材报表后，可以得到下一批素材的测试假设、口播稿、分镜、拍摄任务单、剪辑要求、字幕重点与合规检查。

> 核心目标不是“多生成几条通用文案”，而是帮助编导基于历史证据决定下一批拍什么、只改什么、如何验证。

## V0.3.1 能做什么

### 1. 商品 Brief

- 记录商品、类目、目标人群、痛点、卖点和信任证据
- 记录价格促销、拍摄条件、禁用表达和目标视频时长
- 提供服饰、美妆、食品、家清四类起步模板
- 自动保存在当前浏览器的本地存储中

### 2. 素材复盘

- 导入 UTF-8 CSV / TSV 报表
- 预览前 5 行，避免导错文件
- 自动识别常见千川字段别名，并允许手动调整字段映射
- 明确提示缺失的必需字段和可选指标
- 在分析前补齐或修改人群、前三秒钩子、核心卖点、拍摄场景标签
- 结合样本量、消耗、CTR、CVR 和目标 ROI 输出诊断与置信度
- 导出复盘 JSON 或 Markdown

### 3. 下一批拍什么

- 从表现较好的历史素材中选择基线
- 每轮只测试一个变量：钩子、卖点、场景或人群
- 每个方案包含测试假设、基线、唯一变量、保持不变项、观察指标、最低测试消耗、停止条件和成功后动作
- 根据商品 Brief 生成可编辑的口播稿、镜头级分镜、拍摄任务单、剪辑要求、字幕重点和合规清单
- 自动保存编辑结果
- 支持一键复制，以及 Markdown、CSV、JSON 导出

### 4. 素材库

- 查看当前浏览器内保存的 Brief、复盘素材数和拍摄方案数
- 用 SHA-256 文件指纹和规范化名称，在商家自有目录中寻找同源母版
- 区分“指纹完全一致、名称与大小候选、仅名称候选、未找到”
- 所有文件只在本地读取与计算，不上传素材内容

### 5. 版本与更新

- 显示当前扩展版本和最新稳定 GitHub Release
- 版本检查使用可选权限；只有用户主动检查或明确开启自动检查后才访问 GitHub
- 自动检查最多每天一次，并且只在用户打开侧边栏时运行
- 远端响应只作为版本元数据处理，不下载、不执行、不注入远程代码
- 发现新版本后，必须由用户再次确认才会打开项目 Release 页面
- 支持在更新前导出工作区备份，并在需要时重新导入
- 检查失败时保留当前版本，不修改扩展文件或工作区

## 标准工作流

```text
填写并保存商品 Brief
→ 导入千川素材报表
→ 检查字段映射与数据预览
→ 补齐素材标签
→ 完成历史素材复盘
→ 选择本轮唯一变量与最低测试消耗
→ 生成并编辑策略、脚本、分镜和拍摄任务
→ 导出给编导、拍摄和剪辑执行
→ 上线后重新导入结果，进入下一轮验证
```

V0.3.1 目前保存最近一个工作项目。多项目、脚本版本与投放结果自动回填属于后续版本范围。

## 安装

1. 下载或克隆本仓库。
2. 打开 Chrome 的 `chrome://extensions`，或 Edge 的 `edge://extensions`。
3. 开启“开发者模式”。
4. 点击“加载已解压的扩展程序”。
5. 选择本仓库根目录，即包含 `manifest.json` 的文件夹。
6. 点击扩展图标，在浏览器侧边栏中打开工作台。

扩展使用 Manifest V3，需要 Chrome 114+ 或对应版本的 Chromium Edge。

## 更新方式：必须区分安装渠道

### 从 Chrome Web Store 安装

普通 Windows 用户只有通过 Chrome Web Store 安装的正式版本，才能由 Chrome 按商店机制自动更新。扩展开发者不需要、也不应该把签名私钥放入仓库或扩展包。

### 使用“加载已解压的扩展程序”

Chrome 不会自动替换本地源码目录。V0.3.1 的“自动检查”只负责发现新版本并提示，不会伪装成静默安装：

1. 在“素材库 → 版本与更新”中点击“检查新版本”，或主动开启“打开侧边栏时自动检查”。
2. 首次检查时确认仅访问 `api.github.com` 的可选权限。
3. 发现新版本后，先点击“导出工作区备份”。
4. 点击“确认并打开下载页”，阅读项目 Release 说明并下载源码包。
5. 复制当前扩展目录作为文件备份，再把新版本文件放回原目录。
6. 打开 `chrome://extensions`，在该扩展卡片上点击“重新加载”。
7. 如果新版本无法运行，恢复刚才备份的旧文件，再次点击“重新加载”；需要时导入工作区备份。

保持原扩展目录路径有助于继续使用同一份本地扩展数据。不要把 `.pem` 私钥提交到 GitHub、发送给他人或打包进 Release。

### 企业自托管

Chrome 的自托管扩展更新适用于受企业策略管理的浏览器，不是普通用户“加载已解压”模式的通用替代方案。本项目没有加入会误导用户的 `update_url`。

### 与旧版 douyin-agent 的区别

旧 douyin-agent 的自动切换对象是由本地 Agent 管理的签名知识包：下载后需要验证 HTTPS、SHA-256、Ed25519 签名、版本兼容性和有效期，再原子启用并保留回滚副本。它同样明确要求程序和浏览器扩展使用签名安装包，并没有让“加载已解压”的扩展静默覆盖自身。

当前项目没有常驻本地 Agent，因此只复用其“失败关闭、状态透明、用户确认、保留回退”的原则。完整设计见 [`docs/UPDATE_ARCHITECTURE.md`](docs/UPDATE_ARCHITECTURE.md)。

## CSV 字段

只有以下两个字段是必需的：

| 标准字段 | 常见别名示例 | 是否必需 |
|---|---|---|
| 素材名称 | 素材名称、创意名称、广告创意名称、视频名称 | 是 |
| 消耗 | 消耗、总消耗、广告消耗、花费、spend | 是 |
| 展示量 | 展示量、曝光量、impressions | 否 |
| 点击量 | 点击量、组件点击量、clicks | 否 |
| 成交订单 | 成交订单、支付订单量、orders | 否 |
| 成交金额 | GMV、成交金额、支付金额 | 否 |
| 支付 ROI | 支付ROI、整体支付ROI、ROI、ROAS | 否 |
| 人群标签 | 人群、目标人群、人群标签 | 否，可在扩展内补齐 |
| 前三秒钩子 | 钩子、前三秒、开场钩子 | 否，可在扩展内补齐 |
| 核心卖点 | 卖点、核心卖点、利益点 | 否，可在扩展内补齐 |
| 拍摄场景 | 场景、拍摄场景、使用场景 | 否，可在扩展内补齐 |

缺少成交金额或 ROI 时，扩展无法可靠计算混合 ROI；缺少展示、点击或订单时，对应的 CTR、CVR 和诊断维度会降级。界面会明确显示这些缺失项，不会伪造数据。

## 示例

- [`examples/sample-report.csv`](examples/sample-report.csv)：可直接导入的素材报表
- [`examples/sample-brief.json`](examples/sample-brief.json)：商品 Brief 示例

用示例完成主链路：

1. 根据 `sample-brief.json` 填写“商品 Brief”。
2. 在“素材复盘”导入 `sample-report.csv`。
3. 检查自动字段映射，修改任意素材标签并点击“完成复盘”。
4. 在“下一批拍什么”选择“前三秒钩子”，最低消耗填写 `500`。
5. 生成四条同基线、同卖点、同场景，仅钩子不同的生产任务。

## 规则说明

V0.3.1 使用可审查的本地规则，不依赖远程模型：

- 以非零消耗中位数作为基础样本门槛
- 同时参考展示量、CTR 中位数、CVR 中位数和目标 ROI
- 低样本素材只标记为“待验证”，不会直接认定为失败
- 策略先选择历史表现较好的素材作为基线
- 同一批方案只改变用户选择的一个变量
- 文案与生产资料只使用 Brief、历史标签和合规模板组合生成

这些结论用于辅助编导决策，不等同于因果证明。正式投放前仍需由编导、投手与合规负责人复核商品事实、样本量和平台规则。

## 隐私与安全边界

- Brief、复盘摘要、策略与编辑内容只保存在当前浏览器的 `chrome.storage.local`。
- 原始 CSV、视频、图片和母版文件不会上传，也不会自动写入磁盘。
- 扩展不读取千川账号密码，不注入千川页面，不拦截平台网络请求。
- 扩展不包含远程托管代码。
- 版本检查只在用户主动触发或明确开启自动检查后，向 GitHub API 请求本项目公开 Release 元数据；不会发送 Brief、报表、脚本或素材。
- GitHub API 访问是可选主机权限；未授权时不会发起检查。
- 母版匹配只帮助商家寻找自己拥有版权的源文件。
- 不提供暗水印检测、定位、移除、破解、规避或平台风控绕过功能。

需要干净素材时，应回到商家自有原片、原始工程或已授权素材重新导出。详见 [`PRIVACY.md`](PRIVACY.md)。
